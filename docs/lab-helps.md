# Lab helps: without and with

Generated by `scripts/lab_helps_doc.py`. Some engines cannot connect to a catalog with their stock setup, but a sensible workaround gets them there (list: `iceberg_lab.config.HELPS`). The lab applies it in every run, and a test that works with it counts as working - that is the comparison. The gap itself is shown once per engine by `tests/security/test_stock_connection.py` (area "Connection without help"). The run without help (`LAB_NO_HELP=1`) runs the tests of these engines once more without the workaround; it is shown here and in the dashboard next to the comparison, never counted.

## RustFS

- **pyiceberg, polars, daft**: PyIceberg's SigV4 adapter sends x-amz-content-sha256 only for empty bodies; RustFS rejects every signed POST without it - help: the lab adds the header to every signed request (engines._add_content_sha256).
- **duckdb**: DuckDB derives the SigV4 service from an AWS host name; rustfs:9000 cannot be attached - help: the lab attaches the catalog under an AWS-style alias of RustFS (RUSTFS_AWS_HOST).

### Further known gaps behind it

- RustFS catalog does not support format v3 (406 unsupported format-version: 3; Trino only reports 'Failed to create transaction') (230×, e.g. `tests/engines/test_concurrency.py::test_concurrent_appends[pyiceberg-v3]`)
- DATA LOSS: PyIceberg writes a NULL list<struct> as [] (Polars writes through it) (14×, e.g. `tests/engines/test_types.py::test_read[pyiceberg-pyiceberg-v2-list_of_struct]`)
- DuckDB reads only Parquet data files (8×, e.g. `tests/engines/test_file_formats.py::test_read_format[spark-duckdb-orc]`)
- PyIceberg 0.12 writes only Parquet data files (refuses ORC/Avro) - Polars writes through it (4×, e.g. `tests/engines/test_file_formats.py::test_write_format[pyiceberg-orc]`)
- Daft cannot read DuckDB's nested Parquet lists ('list type must have a single child') - also pg_lake's, which writes through DuckDB (3×, e.g. `tests/engines/test_evolution.py::test_nested_evolution_read[duckdb-v2-daft]`)
- Manifests are written without the 'schema-id' key-value metadata the spec requires from v2 on: PyIceberg (also for Polars and Daft) and Iceberg Java, the reference implementation (Spark, Trino, Flink) (3×, e.g. `tests/engines/test_file_spec.py::test_manifest_schema_id[pyiceberg-v2]`)
- PyIceberg ignores the table's sort order when writing (Polars and Daft write through it) (3×, e.g. `tests/engines/test_layout.py::test_sort_order_honored[pyiceberg]`)
- Spark has no TIME type (3×, e.g. `tests/engines/test_types.py::test_read[pyiceberg-spark-v2-time]`)
- WRONG RESULT: Flink 2.3 reads TIME with millisecond precision only (Iceberg time has microseconds) (3×, e.g. `tests/engines/test_types.py::test_read[pyiceberg-flink-v2-time]`)
- DuckDB gives up a conflicting commit after 5 attempts (4 retries, as many as Iceberg Java's and PyIceberg's default) - with 4 or more writers committing at once all 5 can conflict (409) (2×, e.g. `tests/engines/test_concurrency.py::test_concurrent_appends[duckdb-v2]`)
- DuckDB 2.0.1 writes only Parquet data files (refuses ORC/Avro; 2.0.0 wrote Parquet instead of the requested format) (2×, e.g. `tests/engines/test_file_formats.py::test_write_format[duckdb-orc]`)
- Daft ignores write.format.default and writes Parquet instead (2×, e.g. `tests/engines/test_file_formats.py::test_write_format[daft-orc]`)
- RustFS catalog rejects DROP with purge (purgeRequested=true -> 406), and clients may not delete table files themselves (403) - Spark, Trino and Flink DROP fails (2×, e.g. `tests/engines/test_maintenance.py::test_maintenance[pyiceberg-drop_table-v2]`)
- DuckDB: no PRIMARY KEY / identifier fields on Iceberg tables (only NOT NULL) (2×, e.g. `tests/engines/test_operations.py::test_operation[duckdb-identifier_fields-v2]`)
- DuckDB writes fixed[4] as variable-length binary (2×, e.g. `tests/engines/test_types.py::test_read[duckdb-pyiceberg-v2-fixed_4]`)
- WRONG RESULT: PyIceberg reads a NULL list<struct> as [] (2×, e.g. `tests/engines/test_types.py::test_read[duckdb-pyiceberg-v2-list_of_struct]`)
- RustFS refuses DuckDB's SigV4-signed request for a nested namespace (separator %1F in the path) with 403 - PyIceberg's signed requests for the same path work (1×, e.g. `tests/catalog/test_namespaces.py::test_namespace[duckdb-nested]`)
- DuckDB's compaction (iceberg_rewrite_data_files) while DuckDB appends to the same table fails on the conflict (409, or 'table snapshot changed between planning and execution') - Spark and Trino finish both (1×, e.g. `tests/engines/test_concurrency.py::test_append_during_compaction[duckdb-v2]`)
- WRONG RESULT: PyIceberg 0.12: two concurrent upserts of the same new key both succeed - the loser's retry re-appends its row without checking for concurrent inserts (0.11.1 raised CommitFailedException) (1×, e.g. `tests/engines/test_concurrency.py::test_concurrent_upsert_same_key[pyiceberg-v2]`)
- PyIceberg 0.12 expire_snapshots only removes snapshots from the metadata; data files, manifests and manifest lists stay in storage (1×, e.g. `tests/engines/test_maintenance.py::test_maintenance[pyiceberg-expire_snapshots-v2]`)

- DuckDB DROP TABLE does not request a purge (purgeRequested=false), so Lakekeeper keeps the data files (1×, e.g. `tests/engines/test_maintenance.py::test_maintenance[duckdb-drop_table-v2]`)
- PyIceberg 0.12 deletes only copy-on-write (rewrites the data file) and ignores write.delete.mode=merge-on-read (1×, e.g. `tests/engines/test_operations.py::test_operation[pyiceberg-delete_merge_on_read-v2]`)
